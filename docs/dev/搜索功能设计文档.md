# 生物辞典搜索功能：需求分析与设计

> 状态：修订设计稿，待作者审阅（分支 `dev-search`，基于 `main-26.3`、mod v1.3.2、MC 26.3）。§3 记录原设计阶段的现状；§4 是建议采用的设计；§5 保留需要实测或作者决定的问题。本次只修订文档，不代表功能已经实现。

## 1. 背景与目标

生物辞典的实体列表目前只能靠"全部实体"书签和标签目录逐页翻找，模组环境下实体类型可达上千，定位某个生物的成本很高。本特性给辞典增加一个与书签并列的检索入口：

- **简单搜索**面向普通玩家：不需要任何语法，往输入框里输入关键词即可；
- **高级搜索**面向进阶玩家：完整的布尔表达式与字段前缀；
- 分类入口复用现有书签体系：在分类树里点选分类即把它加入 AND 过滤，已选分类在输入框下方的 chips 行里可见、可点掉；
- 群系、结构等分类数据只有服务端持有，需要新增下发通道。

## 2. 需求

### 2.1 功能需求

| # | 需求 | 说明 |
| --- | --- | --- |
| FR1 | 搜索入口按钮 | 位于书本**右侧、书页之外**，与左侧那排突出在书本外的书签镜像对称（自 `pageTop` 起竖排、突出书页外）；不复用 `Bookmark` 体系，是独立元素。美术资源后补，先以线条/平涂框占位 |
| FR2 | 独立搜索界面 | 基于 `AbstractBiologyDictionaryScreen` 新建独立 screen，记录来源界面并支持返回 |
| FR3 | 输入行独立于二次缩放 | 输入行及其附属控件使用原版屏幕坐标，不参与本模组的 `screenScale` 二次缩放；固定在书本材质之上；越出屏幕上沿时贴屏幕最上沿显示 |
| FR4 | 原版输入框 | 使用 MC 现成的 `EditBox`；进入界面时焦点默认落在输入框上；只有聚焦时可输入 |
| FR5 | 回车/按钮才检索 | 输入过程不实时过滤，按回车或点搜索按钮才执行检索 |
| FR6 | 双模式 | 简单搜索与高级搜索两种模式，界面上可切换 |
| FR7 | 简单搜索模式 | 只有一个输入框，按空白分词；**除关键词外没有任何语法**——`&&`、`\|\|`、`!`、括号、引号、`AND`/`OR` 都只是普通字面量，不需要也不支持转义（全角标点同理）。关键词之间 AND；完整条件 = 全部关键词命中且全部已选分类命中（FR18）。不存在表达式语法错误，但正则/完整匹配/区分大小写同样适用，且可能有依赖数据不可用的错误 |
| FR8 | 简单模式的检索字段 | 关键词在哪个字段里匹配：名称 / 实体 ID / 类-接口（群系、结构等数据通道就绪后再加）。分类不再作为文本字段，改用分类过滤（FR18）。当前实现是“单字段切换”，是否改回“多字段勾选、关键词在所选字段之间 OR”见 §5 |
| FR9 | 高级搜索模式 | 表达式 `&&`、`\|\|`、`!`、`()`，优先级 `!` > `&&` > `\|\|`；字段值可写成 `前缀:"值"` 或省略引号的 `前缀:值`（规范化打印统一输出带引号形式）；**裸词等价于 `name:"词"`**，连续裸词之间隐式 AND。支持中文内容，不把 `AND`/`OR`/`NOT` 或全角标点当运算符；非法表达式明确报错 |
| FR10 | 字段前缀 | 一律“前缀 + 冒号”：裸写取稳定标识，加 `_name` 后缀取名字（当前语言 + 英 + 中的翻译名）。五对：`id:` / `name:`、`tag:` / `tag_name:`、`class:` / `class_name:`、`biome:` / `biome_name:`、`structure:` / `structure_name:`；另有布尔字段 `discovery:`。字段名用 lower_snake_case、大小写不敏感，规范化打印统一输出小写形式。分类的覆盖范围与稳定标识见 §4.7 |
| FR11 | 检索选项 | “完整匹配”“区分大小写”“正则”两模式均有，默认全部关闭。选项由整条查询共享，作用于文本字段值（简单模式下作用于每个关键词），不影响表达式语法与 `discovery:` |
| FR12 | 模式切换 | 切走时暂存当前模式的文本与选项，切入时直接恢复目标模式的状态；首次切入为空串，不自动转换或执行 |
| FR13 | `name` 的跨语言检索 | `name` 匹配当前语言 + 英文 + 中文；实现见 §4.7 |
| FR14 | 结果分页展示 | 结果用现有 `Page` 网格展示；未执行检索时（含刚进入界面）显示全部生物，检索后显示命中的生物 |
| FR15 | 结果区统计 bar | 用一个新的 bar（如"检索到 xx 个生物"）替换主页那对左右工具条 |
| FR16 | 左侧书签复用为分类入口 | 顺序与主页相近（返回主页 + 各分类书签），但不显示设置与关于；除主页已有分类外，增加按群系、按结构分类。书签进入该分类方式的分类树，用于挑选过滤条件（FR18） |
| FR17 | 分类树的预览与勾选 | 分类以树展示，可原地展开/收起子分类。鼠标悬浮某个分类时，该行**内部右侧**出现一个“预览”按钮，点击它把列表内容换成该分类的全部生物；点击行内其它区域 = 勾选/取消勾选该分类（两种模式的落地见 FR18） |
| FR18 | 分类行的勾选（两种模式） | **简单模式**：勾选 = 把该分类加入输入框下方的 chips 行（与关键词、与其它已选分类都是 AND），取消 = 从 chips 移除，都不碰输入框文本；勾选后立即应用过滤并把列表换成检索结果。**高级模式**：勾选 = 往表达式追加 `tag:"<该分类稳定标识>"`，取消 = 从表达式移除该项，沿用“串尾非 `&&`/`||` 时自动补 `&&`”的追加规则与按解析结果的移除规则（§4.6.1）；因为改的是输入框文本，仍需回车/点检索才生效，**不**自动跳结果。两种模式都在分类树里显示勾选态；chips 只有简单模式有。名字形式（`tag_name:`）的入口待定，见 §5。主页没有这个概念 |
| FR19 | 群系/结构索引同步 | 进入世界时独立请求服务端索引，压缩传输，客户端不落盘；区分加载中、失败、就绪。查询涉及不可用维度时整次失败，保留上次成功结果 |
| FR20 | 结果页卡片交互 | 检索结果（以及默认的"全部生物"）沿用主页卡片逻辑：点击打开详情、右键高亮等，不存在写入 id 的诉求 |
| FR21 | （未来）检索结果保存为分类 | 把某个检索条件的**结果集**（执行时的命中实体类型集合）保存为“默认”分组（`defaultTags`）下的一个新分类，之后可像普通分类一样浏览与进入。本次只记录、不实现 |

> `discovery:` 是可序列化的查询条件；“仅已发现”是查询之外的显示过滤。两者取交集，不互相覆盖，统计与空结果提示必须体现这一层过滤。
>
> 字段名风格：`lower_snake_case`、大小写不敏感。未来若增加中文前缀（如 标签 / 标签名 / 类 / 类名），沿用同一套规则——中文没有大小写，正好与不敏感设定一致。

### 2.2 非功能需求

- **查询可序列化、可往返**：完整语义不止查询串——还包括模式、匹配选项、检索字段与已选分类集合，需要一并记录。高级表达式“解析 -> 打印 -> 解析”语义相同，规范化打印再次执行应幂等。
- **模式隔离**：两种模式各自持有一份输入与选项，互不干扰（FR12）。
- **错误不改变结果**：语法、正则或依赖数据错误都不覆盖上次成功的查询与结果；待编辑的输入和已执行的查询分开记录。
- **首版范围**：先落 26.3 的 Fabric / NeoForge；回车触发全量扫描，保持既有排序，不限制结果数。性能以实际模组环境验收。

### 2.3 范围外（明确不做）

- 实体搜索别名的注册接口（作者明确"先算了"）。
- FR21“检索结果保存为分类”本次只记录、不实现。
- 首版不做相关度排序、命中高亮、查询历史与自动补全。

## 3. 现状梳理

### 3.1 主界面与实体列表

- 主界面 `BdHomeScreen` 是实体列表的唯一入口。书签分两类：`AllEntitiesBookmark`（全部实体）与每个 `TagGroup` 一个 `TagGroupBookmark`；后者进入标签目录（`TagCatalog`），点某个 `Tag` 后才列出该标签下的实体。
- 列表数据来自 `EntityManager`：全部实体为 `getEntityEntries()`，标签内为 `Tag#getEntities()`。元素类型 `EntityDictionaryEntry` 携带 `EntityType<?>`、可选实体类、`Identifier`、`namespace:path` 字符串 ID 与 `sortId`（排序号）。
- 列表按 `Page`（9 行 × 8 列）分页渲染，`resetAndAddEntityWidgets` 负责重建卡片、刷新左右/右上工具条并重置页码。
- 卡片显示实体名（`EntityUtils.getEntityTypeNameText`，即当前客户端语言的翻译名）；未发现实体显示 `??`，且 `BdEntityOverviewScreen.canOpen` 会拦住非创造模式的未发现实体。

### 3.2 书签布局与"右上角"

- 书签是 `AbstractBiologyDictionaryScreen` 里长度 10 的 `Bookmark[]`，由 `resizeBox` 统一摆在**书本左侧、书页之外**（`leftPageLeft(width) - box.getWidth() - 19`），自上而下竖排，悬浮时向左外滑一格。`Bookmark` 是 `ScreenElement` 子类，走二次缩放坐标系。
- 每格高 `Widget.WIDGET_HEIGHT`(10) + 4 = 14，10 格约占 136px，可用竖向空间约 `BOOK_HEIGHT`(192)。主页现在用掉 8 格（关于、设置各占末尾一格，全部实体 1 格，5 个 `TagGroup`）。FR16 的 8 格（返回主页 + 5 分组 + 群系 + 结构）同样放得下，再增分组就接近上限。
- FR1 的搜索按钮是书签的右侧镜像，可参照 `rightPageLeft(width) + Page.PAGE_WIDTH + 19`，纵向从 `pageTop(height)` 起按 `box.getHeight() + 4` 递增；`resizeBox` 是统一的布局入口。
- `BdHomeScreen.upperRightToolBar`（仅已发现过滤器、选择模式按钮）位于**书本内部右页上沿之外**，与书外右侧的搜索按钮不在同一区域，两者不冲突。
- 现有按钮风格参考 `gui/component/LongButton`：平涂矩形 + 悬浮提亮，注释里已注明"美术就绪后换贴图"，适合作为 FR1 的占位。

### 3.3 列表视图需要抽成共享

主页的列表视图实现目前**全部是 `BdHomeScreen` 的私有成员**。下面列出现有耦合点，实施时只抽取搜索界面实际需要的部分：

- 取数与卡片：`getEntityWidgets`、`EntityCardWidget`、`EntityActionCardWidget`、`EntitySelectionCardWidget`。
- 工具条：`createUpperRightButtons`、`DiscoveredEntityFilterButton`、`EntitySelectionModeButton`、`EntitySelectionCountDisplay`、`AddToBlacklistButton`，以及 `DiscoveryProgressWidget`、`DecorativeBarWidget`、`setToolBars` 与 `resizeBox` 中的工具条布局。
- 选择模式的进入/退出、选中集合、黑名单动作也都在 `BdHomeScreen` 内部。
- 卡片只有一种：主页与搜索结果都用"左键详情、右键高亮"的卡片；分类树的行沿用现有 `Catalog`（可扩展出预览按钮），不再需要"写入按钮卡片"。抽取时拆成"公共卡片基类 + 主页式卡片"即可。
- 首版需要抽取卡片与选择模式（多选、选择计数、加入黑名单），因为结果区保留这些按钮；发现进度条与装饰条由新的统计 bar 替换（FR15）。优先在 `gui/component/` 提取卡片与必要列表逻辑；不要为了复用少量行为把搜索界面继承自主页。

其它可复用的既有机制：

- "仅已发现"是客户端内存态 `BiologyDictionaryClient.shouldShowOnlyDiscoveredEntities()`（初值取自客户端配置 `showOnlyDiscoveredEntitiesByDefault`），在 `getEntityWidgets` 里逐条过滤，切换时用 `rebuildEntityWidgets(getCurrPageIndex())` 重建。
- 视图重建的既有模式是"整表重建 + 保留页码"（`resetAndAndWidgetsOneByOne` + `setCurrPage`），结果分页可以复用。

### 3.4 原版 widget 的接入点

- 本模组目前**没有任何原版 `AbstractWidget` 的使用**，`addRenderableWidget` 尚未出现过。
- `AbstractBiologyDictionaryScreen#resize()` 里已留好注释 `// Add some vanilla-widgets here.`；`CommonScreen#init()` 是 final 的，`Screen#rebuildWidgets()` 会先 `clearWidgets()` 再 `init()`，所以在 `resize()` 里挂 widget 不会重复累积。
- 原版 widget 由 `CommonScreen#afterRender` 在 `scaleToOriginalOnce()` 下经 `super.extractRenderState(...)` 绘制，即**原始屏幕坐标系**，天然不受二次缩放影响，与 FR3 一致；代价是它画在自定义元素之上，且与书本贴图的相对位置只能按原始坐标估算。
- 命中测试也是分开的：`CommonScreen#mouseClicked` 先用二次缩放后的坐标喂自定义元素，未被消费时才把原始 `MouseButtonEvent` 交给 `super.mouseClicked`，原版 widget 拿到的正是原始坐标。

### 3.5 文本输入与键盘事件的约束

- `EditBox#setResponder(Consumer<String>)` 是**每次文本变化**的回调，不是回车回调；MC 26.3 的 `EditBox#keyPressed` 只处理删除、方向键、全选、复制、粘贴、剪切、Home/End，**不消费回车**；原版 `Screen#keyPressed` 也不处理回车。所以"回车才检索"必须在 `screen#keyPressed` 里自己判断回车。
- `Screen#setInitialFocus()` 仅在"上一次输入类型是键盘"时才自动聚焦第一个可聚焦 widget（手柄或纯鼠标进入不会自动聚焦），FR4 的"默认聚焦"需注意这一前提。
- 输入法：`EditBox` 实现了 `charTyped` 与 `preeditUpdated`，且本模组的 `CommonScreen`/`ElementScreen` 都没有覆盖 `charTyped`，所以只要焦点在原版 widget 上，中文输入法即可正常工作。
- **冲突**：`AbstractBiologyDictionaryScreen#keyPressed` 目前在按下 `KeyMappings.OPEN_HANDBOOK`（反引号）或 `client.options.keyInventory`（E）时直接 `onClose()`；而原版派发顺序是"先给子类、再给焦点 widget"，所以在输入框里打字 `e` 会先关屏。落地时必须让位于输入焦点。
- `ElementScreen` 的自定义元素体系只有鼠标（`ScreenElement#mouseDown`），没有焦点与键盘概念，因此输入框无法套用自定义元素框架。

### 3.6 名称来源

- **实体**：当前语言显示名取自 `EntityType#getDescription()`（`EntityUtils.getEntityTypeNameText`）；id 为 `Identifier`（`namespace:path`）；类名可用 `EntityManager.getClassRealName`（26.x 不混淆），但 `EntityDictionaryEntry#getClazz()` 可能为空。
- **实体名的跨语言读取**（FR13 的依据）：`Language.DEFAULT_INSTANCE` 只加载原版内置的 `assets/minecraft/lang/en_us.json`，不含模组实体。`Minecraft#getResourceManager()` 提供命名空间和资源读取入口，`Resource#open()` 拿到流后可用 `net.minecraft.locale.Language.loadFromJson(InputStream, BiConsumer)` 解析。原稿考虑只读有实体的命名空间；修订方案需覆盖其它命名空间提供翻译和资源包局部覆盖的情况，具体读取与合并规则见 §4.7。
- **分类（`Tag`）**：`Tag` 构造里 `text = TextUtils.translate(name)`，即 `name` 本身就是翻译 key，显示名来自翻译。模组的 lang 文件确实为原版内容提供了条目——`net.minecraft.*` 155 条（类/接口的全限定类名）、`minecraft.*` 50 条（MC 标签的 `Identifier#toLanguageKey()`，冒号换点）、`structure.*` 34 条，各有中英文。
- **模组新增的标签/类没有翻译**（无法预先翻译别人的模组），`Component.translatable` 会原样回退成 key 本身（如 `create.something`），可用 `TextUtils.hasTranslation` 判断。
- **key 形态与查询形态不同**：MC 标签的 `Tag.name` 使用点分翻译 key（`minecraft.zombies`），查询需要原始 ID（`minecraft:zombies`）。建立分类数据时保留原始 ID，不能从翻译 key 反向推断；其余分组使用各自的稳定标识，见 §4.7。
- **群系/结构**：显示名同样是翻译 key（`biome.<ns>.<path>`、`structure.<ns>.<path>`），id 即 `<ns>:<path>`。
- **可用的分类数据源**：标签走 `EntityManager.Tag`/`TagGroup`（现有 5 个分组：默认、MC 标签、模组、类、接口）；已发现走 `ClientDiscoveryCacheManager#isDiscovered`；群系与结构走 `EntitySpawnManager`（可用性见 §3.8）。
- **别名**目前只有一处先例且仅针对物品：`compat/jei/BiologyDictionaryJeiPlugin` 给辞典书本注册了 `"生物辞典" / "Biology Dictionary" / "shengwucidian"` 三个 JEI 搜索别名。实体侧没有别名注册表，也没有拼音数据源（本次范围外）。

### 3.7 客户端/服务端边界

- 实体列表、发现缓存、标签分类、"仅已发现"开关全部在客户端，基于这些数据的过滤不需要任何网络包，也不改动服务端配置与发现策略。
- 群系/结构是唯一例外，见 §3.8。

### 3.8 群系/结构数据只在服务端

- `EntitySpawnManager` **只挂在 `ServerWorldSession`**：构造要用 `server.registryAccess()`（需要 WORLDGEN 层注册表）并分析结构模板，是纯服务端设施，`ClientWorldSession` 上没有对应实例。
- 客户端目前只能**按单个实体类型、按需**拿到生成信息：读写封装在 `MobSpawnProperty`，其 `getFrom` 直接取 `ServerWorldSession`，客户端为 null 即置空；数据实际经 `RequestEntityOverviewPacket` -> `SendEntityOverviewPacket`（`EntityOverviewCache`）在打开某生物详情页时同步过来。
- 客户端**没有"群系/结构 -> 实体集合"的全局索引**：`EntitySpawnManager#getBiomeEntities` 是反查 Map，只有服务端持有；`SpawnMap` 也只维护 forward/reverse 两个内部 Map，未暴露键集合。
- 因此 `biome:`/`structure:` 这类检索与群系/结构书签都需要新增数据通道，方案见 §4.8。

## 4. 设计

### 4.1 入口与导航

- 在 `AbstractBiologyDictionaryScreen` 上新增书本右侧、突出书页外的搜索按钮，与左侧书签列镜像对称，布局同样收在 `resizeBox` 里；不复用 `Bookmark` 基类与贴图，美术就绪前用线条/平涂框占位。初始位置参照 §3.2，尺寸细节由作者微调。
- 点击进入独立搜索界面 `BdSearchScreen extends AbstractBiologyDictionaryScreen`，记录来源界面以便返回。搜索界面上的搜索入口只把焦点交给输入框，不再嵌套打开自身。
- 左侧为“返回主页 + 5 个现有分类分组 + 群系 + 结构”，不保留“全部实体”书签。检索结果是列表的默认内容；点“检索”并成功执行即重建结果列表。
- 分类树与分类预览都是**就地替换列表内容**，不新开界面、不维护返回栈：想看分类树就再点一次左侧对应书签，想看检索结果就点检索按钮（重新执行当前输入）。不做“返回上一级”这种按钮。
- Esc 始终关闭搜索界面回到来源界面；输入框聚焦时第一下仍是失焦（§4.2）。左侧“返回主页”始终打开主页。
- 从结果列表打开详情后，详情的返回操作回到搜索界面并保留页码。具体接入现有导航的方式在实现前核对。

### 4.2 搜索界面与输入行

- 输入行是 `[检索] [文本框] [字段切换]`（当前实现）；模式切换按钮留到引入高级模式时再加，位置与形态届时确定。各部分等高、整体居中，两端是 16×16 的贴图按钮。
- **仅简单模式**：输入行下方是已选分类行，一个 chip 对应一个已选分类（当前语言显示名），点 chip 上的关闭即取消该分类；没有已选分类时不显示这一行。行宽不足时换行；行数与是否压到书页留待实测（§5）。高级模式不显示这一行，条件一律写在表达式里。
- chip 是点选式过滤，增删后立即重算结果（仅简单模式）；输入框文本仍然只在回车/点检索时生效（§4.3）。两者对“上次执行状态”的提示需要分开，见 §5。
- 输入行及附属交互控件全部使用原版 widget；输入框使用 `EditBox`，按钮与开关也使用原版组件。
- 无论用鼠标还是键盘进入，输入框默认聚焦，只有聚焦时可输入。输入框聚焦期间，E/反引号等关屏快捷键让位于文本输入，与框内是否有文本无关。
- 输入框聚焦时回车执行检索；其他原版控件聚焦时回车交给该控件，避免一次按键同时触发按钮与检索。Tab 使用原版焦点遍历，方向键保留输入框编辑行为。
- Esc 不清空文本；有输入法组合文本时先遵循原版输入法处理，未被消费的 Esc 再执行 §4.1 的导航规则。
- 这一行及其附属控件使用原版原始屏幕坐标，不参与 `screenScale` 二次缩放；固定在书本材质之上，越出屏幕上沿时贴屏幕上沿显示。
- 检索失败时在输入框下方显示红字，使用原始屏幕坐标。语法/正则错误指出原因与位置；数据错误指出不可用维度。错误不覆盖结果统计，开始编辑后清除旧错误。
- 输入或匹配选项相对上次执行状态发生变化时显示“条件已修改，尚未检索”，避免把旧结果误认为当前输入的结果。模式切换同样适用；chip 增删是立即生效的，不需要这个提示。
- 窄窗口优先缩短输入框；不足以容纳全部控件时将附属控件换行。输入区域和错误行都需要保留可点击空间，不能只钳制顶部而让控件相互覆盖。

### 4.3 双模式与查询语法

**简单搜索**

- 输入只是一串关键词，按空白字符分词并忽略空词。**没有运算符**：`&&`、`||`、`!`、括号、引号、`AND`/`OR` 都是普通字面量，不需要也不支持转义，全角标点同理；因此不存在表达式语法错误。
- 完整条件 = 每个关键词都命中（AND）∧ 每个已选分类都命中（AND）。两种条件是独立来源：关键词来自输入框，分类来自分类树的点击（§4.6），关键词的字段选择不影响分类过滤。
- 关键词的检索字段：名称 / 实体 ID / 类-接口（群系、结构等数据通道就绪后再加）。当前实现是单字段切换，是否改回多字段勾选见 §5。
- 空白输入且没有已选分类 = 全部实体；只有已选分类而没有关键词 = 这些分类交集的实体，此时不依赖关键词字段的数据；若某个已选分类所属维度尚不可用（如群系索引未就绪），整次报错而不是静默跳过。
- “完整匹配”“区分大小写”“正则”三个选项同样作用于每个关键词，不影响分类过滤。打开正则时，关键词整体按正则解释（如 `Zombie.*`），反斜杠直接交给正则引擎、不做查询层转义。

**高级搜索**

- 输入是表达式，解析成条件 AST：`&&`、`||`、`!`、`()`，优先级 `!` > `&&` > `||`。
- 前缀值有两种写法：带引号的 `前缀:"值"`，或省略引号的 `前缀:值`。省略引号时，值从冒号后一直延伸到空白或运算符字符（`&`、`|`、`!`、`(`、`)`），因此冒号属于值的一部分，`tag:minecraft:zombies` 合法。含空格、引号或运算符内容的值必须用引号；`name:Zombie Villager` 会按常规校验报错，不需要额外的模式匹配，但提示要人性化（直接说明“含空格的值请加引号”）。规范化打印统一输出带引号形式。
- 转义只在带引号形式内有意义，只支持 `\"` 与 `\\`；未知转义、未闭合引号与括号都报错。表达式外围允许空白，**字段名大小写不敏感**（`Tag_Name:` 也收，规范化打印统一输出小写）。
- 裸词等价于 `name:"词"`，多个裸词之间是隐式 `&&`：`Zombie Villager` 即 `name:"Zombie" && name:"Villager"`。因此裸词只搜 `name`，其它字段必须显式写前缀。
- 隐式 AND 仅用于由空白分开的连续裸词；字段条件、括号与其它条件之间必须显式写运算符。`Zombie name:"村民"`、`a(b)` 均报错，避免出现多套隐式连接规则。
- 裸词不能包含 ASCII 语法字符 `:`、`"`、`&`、`|`、`!`、`(`、`)`、`\`；含冒号的裸词（如 `minecraft:zombie`）会因字段名未知而报错，要按 ID 检索请写 `id:minecraft:zombie`。这类内容用 `name:"..."` 表达。中文裸词与引号内中文内容均可正常检索。
- 空白输入表示全部实体；空字段值（`tag:""`）报错，不把空值当通配（否则用户无法判断它的含义）、空括号、未知字段、悬空或连续二元运算符（`a&&`、`&&a`、`a&&||b`）均报错，不自动修复。连续一元取反 `!!a` 合法。
- 普通查询例：`tag:"minecraft:zombies" && (name:"Zombie" || name:"僵尸")`。
- 正则查询例（打开正则）：`name:"Zombie.*" && !biome:"minecraft:.*ocean"`。没有独立的通配符语法；正则关闭时 `.*` 与 `*` 都是字面量。
- 不把 `AND`/`OR`/`NOT` 当运算符，它们作为普通裸词搜索；不把全角标点转换为 ASCII 运算符，它们作为名称内容处理。
- `discovery:"true"` / `discovery:"false"` 仅接受这两个精确值，表示已发现/未发现；不参与文本匹配选项。状态读取现有发现缓存，不重新实现发现策略。

**模式切换**

- 同一时刻只有一个模式生效，输入框只有一份文本。
- 切走时存入当前模式的槽位，切入时直接恢复目标模式的文本与选项；简单模式同时恢复检索字段与已选分类（chips）。高级模式的分类条件存在它自己的表达式里，不与之共享。首次切入另一个模式时使用空串与默认选项，不复制或转换原模式内容。
- 切换本身不执行检索、不清空上次成功结果；清除错误提示并更新“尚未检索”状态。

**两种模式的差异是有意的**：简单模式的 `zombie` 在所选字段上匹配、并叠加分类 chips；高级模式的裸词 `zombie` 只等价于 `name:"zombie"`，分类条件由表达式里的 `tag:"…"` 表达（§4.6.1）。

### 4.4 检索选项

- 两种模式都有“完整匹配”“区分大小写”“正则”，默认全部关闭。使用“完整匹配”代替含义不明确的“全词匹配”，不采用英文单词边界规则。
- 选项是整条查询共享的设置，作用于每个文本条件，不作用于字段名、逻辑运算符与 `discovery:`；首版不提供逐条件选项。
- 字面量默认做子串匹配；完整匹配打开时，必须等于某一个完整候选值。例如完整匹配下 `id:"zombie"` 不匹配 `minecraft:zombie`，不会自动补命名空间。
- 正则默认在单个候选值中查找匹配片段；完整匹配打开时要求正则覆盖整个候选值。多个语言名或分类值分别匹配，不拼成一个字符串。
- 不区分大小写的字面量比较使用 `Locale.ROOT` 规范化；正则使用大小写忽略和 Unicode 大小写支持，不对正则表达式本身做小写转换。
- 正则先经过查询字符串反转义，再编译。要把 `\d` 交给正则引擎，查询中写 `name:"\\d"`；目录按钮生成值时需依次处理正则字面量引用和查询字符串转义。
- 所有正则在执行前编译一次，非法正则报错。输入长度与复杂正则的执行耗时在性能验收中评估，不能假定普通线程中断可终止正则匹配。

### 4.5 列表视图与结果展示

- 搜索界面内部有三块就地切换的列表内容，共用同一套 `Page` 网格与分页机制：
  - **结果列表**（默认）：显示全部生物或检索结果，卡片沿用主页逻辑（点击打开详情、右键高亮）。
  - **分类树**：从左侧书签进入，把列表内容换成该分类方式的分类树（“过滤选择器”），见 §4.6。
  - **分类预览**：点分类行里的预览按钮，把列表内容换成该分类的全部生物。
  - 三者都不新开界面、没有返回栈：重新点书签得到分类树，点检索按钮得到结果。
- 命中统计用一个新的 bar（如"检索到 xx 个生物"）替换主页那对左右工具条。
- 未执行检索时显示全部生物；空查询成功执行后也显示全部。成功执行重建结果列表并回到第一页；失败保持当前列表不动。
- 待编辑状态与上次成功执行的查询定义分开保存。修改输入、选项、检索字段或模式不会改变已执行条件与结果。
- 结果保持现有 `sortId` 排序，不做相关度排序或命中高亮。结果以实体类型去重，继续使用现有分页，不截断命中列表。
- 保留“仅已发现”、多选/选择计数与加入黑名单，与主页保持一致，状态共享主页的内存态；发现进度条与装饰条由新的统计 bar 替换（FR15）。查询命中集合与显示过滤分开，统计为“命中 N 个，显示 M 个”；若被发现过滤全部隐藏，提示这一原因。
- 发现状态变化时重算上次成功查询（尤其是 `discovery:`），并应用最新显示过滤；不能执行尚未提交的编辑串。语言/资源包索引重建后也重算已执行查询，页码保留并钳制到有效范围。

### 4.6 分类树与分类预览

- 左侧书签顺序与主页相近（返回主页 + 各分类书签），不显示设置与关于，并增加按群系、按结构分类；点书签进入该分类方式的分类树。
- 分类以树展示，可原地展开/收起子分类，展开状态在本次界面内保留。
- **悬浮时的行内按钮**：鼠标悬浮某个分类行，行的**右侧内部**出现一个“预览”按钮，点击它把列表内容换成该分类的全部生物。两种模式都有这个按钮；按钮不挤占行内文字，tooltip 写明“预览该分类下的生物”。
- **行内其它区域点击 = 勾选/取消勾选**该分类，勾选态必须在树里显示（勾选标记或高亮），不能只靠 chips 行反映。两种模式的落地不同：
  - **简单模式**：勾选 = 加入 chips 行（§4.2、FR18），与该分类方式下的其它已选分类、以及全部关键词之间都是 AND；取消 = 从 chips 移除。**不触碰输入框文本**；勾选后立即应用过滤并把列表换成检索结果。
  - **高级模式**：勾选 = 把 `tag:"<该分类的稳定标识>"` 追加进表达式；取消 = 从表达式移除这一项（§4.6.1）。高级模式不显示 chips；勾选态由当前表达式（可解析时）是否含该项推出，表达式非法时不显示勾选态。
- 勾选的分类按“分类方式 + 分类”唯一确定。同一分类方式下可勾选多个，彼此 AND（命中很可能为空，允许并如实显示空结果）；不同分类方式之间也是 AND。
- **勾选父分类时包含其子孙分类的实体**：在查询层展开（沿 `getSons()` 收集），`Category.getEntities()` 本身仍只含直接成员，不改数据。
- 分类树与分类预览都直接复用当前 `Page` 列表：切进去就从第一页开始，切走即丢弃，不保留位置与页码。

#### 4.6.1 高级模式的追加与移除规则

- **追加**：表达式为空时直接写入 `tag:"<id>"`；非空时若串尾不是 `&&` 或 `||`，先补一个 `&&` 再追加，不自动加括号、也不做整体重写。
  - 直接追加的后果：在 `a||b` 后追加会得到 `a||b&&tag:"x"`，按优先级等价于 `a || (b && tag:"x")`；要别的结合方式由用户自己写括号。
- **移除**：按解析结果删除对应的条件项并重新规范化打印，而不是字符串替换——`a && tag:"x" && b` 与 `tag:"x" && a` 都要能正确去掉；表达式非法时拒绝移除，保留原文并报错。
- 写入统一使用带引号形式；正则开启时先把 id 中的正则元字符转义成字面量（类名里的 `.`、内部类名的 `$` 等），避免写入的 id 被当成正则语法。
- 追加/移除改的是输入框文本，因此与手打一样需要回车/点检索才生效，并显示“条件已修改，尚未检索”；不做去重（同一项写两次就是两个条件）。
- **为什么不和简单模式一样立即跳到结果**：这里只是往表达式里追加文本，句子本身可能还不合法（例如串尾是 `||`、或用户正在编辑），直接把结果换掉是错的；所以保持“文本改了但要回车/点检索才生效”。


### 4.7 检索索引

- 索引挂在 `ClientWorldSession`，每个实体保留原始文本和必要的小写缓存；原始文本用于区分大小写与正则，不可只保留小写形式。
- 字段定义由一份表统一管理前缀、候选值来源、简单模式字段与依赖状态，避免界面、解析器和目录按钮各维护一套定义。

| 字段 | 候选值与范围 |
| --- | --- |
| `id` | 完整实体 ID，即 `namespace:path` |
| `name` | 当前语言、英文、简体中文名称；缺失翻译时加入实体 ID，不把未翻译的 key 伪装成名称 |
| `tag` / `tag_name` | 默认分类、MC 标签、模组分组三类的稳定标识 / 名称；类和接口由 `class` / `class_name` 查询 |
| `class` / `class_name` | 实体所属类、父类与接口的全限定名 / 翻译名，复用现有类和接口分组的归属关系 |
| `biome` / `biome_name` | 服务端索引中的生成群系 ID / 名称 |
| `structure` / `structure_name` | 服务端索引中的生成结构 ID / 名称 |
| `discovery` | 当前发现缓存中的布尔状态，只接受 `true` / `false` |

- 分类稳定标识：MC 标签保留原始 `namespace:path`；默认分类使用现有 `Lang.TAG_DEFAULT_*` 对应 key；模组分组使用命名空间。前缀值是字符串，不强制把默认分类或命名空间解析成 `Identifier`。类与接口目录分别生成 `class:` / `class_name:`，不生成 `tag:` / `tag_name:`。
- 默认分类、MC 标签、模组分类可能有相同标识；同一 `tag` 条件匹配任一分类，不默认按分组区分。首版不增加分组限定语法。
- `xx_name` 候选包含当前语言、英文、简体中文可用翻译并去重；缺少翻译时回退到不带 `_name` 后缀的稳定标识。chips 显示分类名，缺少翻译时同样回退到稳定标识。
- 没有实体类的类型，其类/接口候选集合为空；正向 `class:` 不命中，取反可以命中。就绪索引中没有生成关系的实体同理，但这只能表示“索引未记录关系”，不能断言它永不生成。
- 跨语言资源读取按需要的翻译 key 收集，而非只依据实体 ID 的命名空间：翻译资源可能由其它命名空间提供，模组自己的分类翻译也要纳入。按资源优先级合并语言资源，再取出所需 key，释放临时 map；具体 MC API 实现先核对本地 26.3 源码。
- `Language.DEFAULT_INSTANCE` 可提供原版英文基础数据，但不是模组翻译或资源包覆盖的完整来源。当前语言名使用客户端已加载的翻译；另外两种语言的缺失条目使用上述明确的稳定标识回退规则。
- 首次打开搜索界面时建立本地文本索引，每次资源重载/语言切换失效重建；群系/结构关系进入世界时先请求，名字在文本索引中补齐。先实现同步构建，实测发现卡顿再考虑异步，不在工作线程直接访问未经核对的客户端资源对象。
- 重连销毁旧会话与索引。服务端数据刷新或关系索引替换时，重算上次成功查询；尚不可用时保留旧结果并明确标记未更新，不把旧关系冒充新数据。

### 4.8 群系/结构索引同步

- 数据来自服务端的 `EntitySpawnManager`；**进入世界时**用一个独立请求（不并与 config 之类的包混在一起）向服务端索取。
- 生物到群系的映射里有大量重复字符串，直接传体积偏大，因此**压缩后传输**（不给字符串赋 id，避免把传输格式搞复杂）。
- 客户端**不落盘**缓存。
- 单人模式也走同一请求/回复路径，不从客户端直接读取服务端会话；服务端不新增检索权限或开关，本地检索不产生服务端扫描请求。
- 服务端基于已建成的 `EntitySpawnManager` 生成并缓存压缩快照，不因每个玩家请求重新分析结构或重复压缩。索引刷新时使快照失效；已有刷新机制和是否需要增加刷新通知在实现前核对。
- 客户端区分 `loading`、`ready`、`failed`。进入世界请求，30 秒未收到完整回复则标记失败，不自动循环重试；界面提供显式重试入口。已断开会话的延迟回复不能写入新会话。
- 查询在求值前检查全部依赖维度；涉及未就绪或失败维度时整次报错，包括取反与 OR 的分支，不通过短路求值绕过依赖检查。`!biome:"minecraft:plains"` 不能因同步失败变成匹配全部。
- 查询未使用群系/结构时可照常执行；后台同步失败只在对应目录展示状态，不能给无关查询报错。目录分别显示加载、失败或就绪后的空列表。
- 就绪索引只提供现有分析器记录的生成关系，不推断所有模组的运行时生成机制。目录只列至少有一条关系的群系/结构，按稳定 ID 排序；无关系实体仍可通过普通搜索找到。
- 压缩采用 GZIP；协议携带格式版本、快照标识、分片序号/总数和压缩总长度。压缩快照超过单包容量时分片，预留协议头空间，收齐后解压并原子替换索引。
- 明确设置压缩总长度、分片数与解压长度上限，具体值按模组环境样本确定；超限、版本不兼容、解压失败均显式报错，不截断索引。客户端只保留当前请求的分片，完成、超时或断开后释放。
- 新包可参照现有的全量同步先例：`RequestBiologyDictionaryDiscoveryFullPacket` -> `ReplyBiologyDictionaryDiscoveryFullPacket`。
- 包体上限：26.3 原版自定义包为**客户端 -> 服务端 32767 字节、服务端 -> 客户端 1048576 字节**（`ServerboundCustomPayloadPacket` / `ClientboundCustomPayloadPacket` 的常量）。

### 4.9 状态与后续保存

- 会话内保存两种模式的编辑状态、上次成功查询定义、结果/目录位置和页码；返回后再次进入搜索恢复这些状态。来源界面由本次打开记录，不把 screen 对象存进会话数据。
- 不持久化搜索编辑状态到客户端配置；退出世界后清理。窗口 resize 只重建控件和布局，不能丢失输入、焦点、选项或已执行条件。
- 后续 FR21 保存的是**检索结果**（执行时的命中实体类型集合），不随语言、发现状态或生成索引变化。“仅已发现”属于外部显示过滤，不隐含写进结果；需要固定该条件时用 `discovery:` 再执行一次。
- 保存以实体类型为稳定引用（不存名字），名称在展示时按当前语言解析，因此结果对资源包与语言切换稳定。
- 如一并记录来源查询串，高级模式存规范化表达式；持久化格式带版本，未知版本明确报错，不猜测迁移。
- 保存分类未来需要独立存储与重建注入，不让 `Tag.name` 同时承担用户名称、结果集和翻译 key；本次不实现存储，也不预建完整迁移框架。

## 5. 待决问题

本节只保留无法靠文字设计确定的事项；§4 的选择是本稿建议，作者审阅时可直接调整。

1. **布局与美术**：入口按钮、检索/字段按钮、chips 行的尺寸与位置由作者微调；chips 行溢出策略、窄窗口下的错误行与书本内容需实测。
2. **性能阈值**：实测千级实体下的首次语言索引构建、查询与卡片重建耗时，再决定是否异步构建或按页创建卡片。正则的输入长度、复杂表达式耗时与执行策略单独验收；普通查询快不代表正则不会阻塞。
3. **同步容量**：采样大型模组环境，确定压缩总长、分片数、解压长度上限，以及 30 秒超时是否合适；不以原版约 60 个群系、30 个结构估算模组环境上限。
4. **现有机制接入**：实施前核对详情返回、资源重载完成、发现缓存更新和服务端生成索引刷新入口。若现有事件不足，明确新增通知的范围；同步刷新期间不能继续展示未标注的旧结果。
5. **后续范围**：完成 26.3 双端验收后，再由作者决定移植其余版本、自动补全与 FR21。FR21 的存储位置、用户分类重命名及删除规则留到该功能实施时设计。
6. **chips 行细节**：显示顺序按选择顺序、同一分类方式可多选（已实现）；超出宽度时换行，换行上限与是否会压到书页需实测；简单模式勾选后直接换成检索结果，是否需要“留在分类树里连续多选”的变体。
7. **重算时机**：简单模式的 chips 增删立即重算（本稿）；高级模式的追加/移除改的是文本、与手打一致需回车。输入框文本与 chips 的“已执行/未执行”状态是否需要分别提示。
8. **检索字段与匹配选项**：简单模式的关键词字段是单字段切换（现实现）还是多字段勾选（原 FR8）；“完整匹配/区分大小写/正则”（FR11）是否保留、放在界面哪里——当前实现没有这三个选项。
9. **名称形式 `tag_name:` 的入口（需要，形态待定）**：老设计是 id / name 两个按钮；作者倾向改成“一个行内按钮 + tooltip 提示左键写 `tag:`、右键写 `tag_name:`”。两种形态与是否加 tooltip 以后再定，本稿先按只写 `tag:` 实现。


## 6. 实施计划

按以下顺序形成可独立验收的阶段。涉及现有代码抽取时，先确认最小改动范围，不把主页工具条重构作为搜索的整体前置。

1. **查询核心**：建立字段定义、简单模式匹配、高级解析器/AST、匹配选项与规范化打印。用人工构造的数据验证语义，不依赖界面或网络。
2. **本地搜索闭环**：提取必要卡片与列表逻辑，接入搜索入口、原版输入控件、模式暂存、错误提示、结果分页与发现过滤；实现实体/分类文本索引与资源失效处理。此阶段群系/结构入口明确显示尚不可用。
3. **分类过滤**：复用现有五个分类分组做分类树，实现预览、勾选/取消、树内勾选态；简单模式接 chips 与即时重算，高级模式接表达式追加/移除（含自动补 `&&`、按解析结果移除、正则元字符转义）。
4. **生成关系同步**：服务端快照、GZIP 分片协议、客户端状态与重试；接入群系/结构字段和目录，并验证单人、多人与索引更新路径。
5. **完整验收**：中英文与资源包覆盖、输入法、未发现实体、语言/发现状态更新、大型模组性能及 Fabric / NeoForge 双端检查；完成布局微调。FR21 与其它版本移植单独安排。

## 7. 兼容性与测试

**查询核心与状态验证**

- 简单模式：关键词 AND、分类 chip AND（含同一分类方式多选、只有 chips 没有关键词）、空白输入、中文，以及把 `&&`/`AND`/`||`/`!`/括号/引号当字面量。
- 运算符优先级、连续裸词、显式连接、取反、中文值、合法转义；未知字段、空值、未知转义、残缺表达式与未闭合引号/括号均明确失败；字段名大小写不敏感（`Tag_Name:` 等价于 `tag_name:`）。
- 字面量子串/完整匹配、大小写选项、正则查找/完整匹配、非法正则；分类过滤不受这些选项影响。
- AST 解析/打印语义往返与打印幂等；高级模式的非法表达式必须报错且不破坏已执行的结果与用户输入。
- 高级模式从分类树追加/移除 `tag:"…"`：空串直接写入；串尾非 `&&`/`||` 时自动补 `&&`（`a||b` 后追加得到 `a||b&&tag:"x"`）；按解析结果移除（`a && tag:"x" && b` 与 `tag:"x" && a` 都要能去掉）；表达式非法时拒绝写入且原文不丢失；正则开启时 id 中的元字符被转义。
- 原始 ID 与翻译 key 分离、父类/接口归属、缺翻译回退、空候选集取反，以及查询定义连同选项的往返。
- 模式暂存、编辑与已执行状态分离、失败保留结果、发现过滤统计；加载失败不能通过取反或 OR 短路伪装成有效查询。
- 索引压缩/分片/重组与原子替换、超限及损坏数据、超时释放、重试与旧会话回复隔离。

**手动验收**

- 中英文客户端、模组实体、翻译资源位于不同命名空间、资源包局部覆盖，以及切换语言/资源包重载后的已执行查询重算。
- 纯鼠标进入时默认焦点、输入 E/反引号、中文输入法提交与 Esc、回车不重复触发、Tab 遍历、窗口 resize 与窄窗口控件命中。
- 默认全部实体、零命中、多页结果、结果卡片详情/高亮、分类树展开/选中/chips 取消与按钮命中不穿透、从详情返回、退出再进入与断开清理。
- 三种 `discoveryStrategy` 下统一读取缓存；未发现卡片与详情限制不被绕过；chips 只显示分类名、不泄露任何实体名；发现状态变化后更新结果。
- 单人和多人服务器、进入世界后索引尚未就绪、同步失败/显式重试、大快照分片、服务端索引刷新，以及没有生成关系的实体。
- 大型模组环境记录索引构建、查询与卡片重建耗时；正则复杂输入单独验证。按测量结果处理瓶颈，不提前引入完整倒排索引。

Fabric / NeoForge 的网络协议与界面均需验证。服务端通道使用 `fabric:runTestServer` 进行集成验证，并补 NeoForge 联机验收；`check` 与双端构建按阶段执行。所有 Gradle 命令串行运行，daemon、依赖、缓存或 I/O 出错时先停止并说明现象。
